# Chararium

Chararium は、AI 連動デスクトップマスコットアプリを段階的に構築するための Electron + React + TypeScript ベースの初期開発環境です。

現時点では、通常ウィンドウと透明マスコットウィンドウの土台、ローカル返答モード、吹き出しプレビュー、テーマ切替、多言語化を見据えた文字列分離までを実装しています。

## Character Renderer 方針（2026-04-25更新）

- Chararium は将来的に Live2D / 3D の両対応を目指します。
- 初期状態では `PlaceholderRenderer` による `Mascot Placeholder` 表示を標準実装としています。
- 表示方式は設定画面のレンダラー選択UIで `プレースホルダー` / `Live2D` / `3D` を切り替えできます。
- Live2D と 3D は現時点では準備中表示で、アプリが落ちない差し替え基盤のみ実装しています。
- Live2D は `.model3.json` 起点で読み込む予定です（`.moc3` 単体運用は想定しません）。
- 3D は `.vrm` / `.gltf` / `.glb` 対応を検討しています。
- Live2D SDK や three.js / VRM ローダー等の実導入は後続タスクで行います。

## モデル管理（2026-04-25更新）

- 設定画面にモデル管理セクションを追加し、モデル検出・一覧表示・選択・選択情報プレビューを実装しています。
- 現時点では実描画は行わず、後続の Live2D / 3D 実表示へ接続するための管理基盤を提供します。
- Live2D モデル配置場所: `assets/live2d`
- 3D モデル配置場所: `assets/models3d`
- 検出対象形式:
  - Live2D: `.model3.json`
  - 3D: `.vrm` / `.gltf` / `.glb`
- モデル選択時は形式に応じて表示方式を自動切替します（Live2D -> `live2d`, 3D -> `3d`）。

## 3D / VRM 初期表示（2026-04-25更新）

- 3D 表示方式で、選択した `.vrm` を実際にプレビュー描画できる初期対応を追加しました。
- `.vrm` は `assets/models3d` 配下に配置してください。
- 配置例: `assets/models3d/mai_uniform_v0.vrm`
- `.gltf` / `.glb` は検出対象ですが、実描画は後続タスクで追加します。
- Live2D の実描画も後続タスクで追加します。
- 3D/VRM 表示に使用するライブラリ:
  - `three`
  - `@pixiv/three-vrm`
- VRM表示では、Tポーズを避けるために暫定の初期待機ポーズ補正（腕を下げる軽い補正）を適用しています。
- 本格的なモーション再生（VRM Animation / 外部モーション）は後続タスクで実装します。

## マスコットウィンドウ表示整理（2026-04-25更新）

- マスコットウィンドウは通常時、キャラクター本体と吹き出しを中心に表示します。
- モデル名・形式・パスなどの詳細情報は、マスコットウィンドウ内の `詳細` ボタンで表示/非表示を切り替えできます。
- タイトルバーなしウィンドウでも、マスコット表示領域のドラッグでウィンドウ移動できます。
- メイン画面プレビュー側では従来どおりモデル情報を確認できます。
- 通常表示は透過UIを優先し、キャラクター本体・吹き出し・吹き出し付近の小さな詳細ボタンのみを基本表示にしています。
- 吹き出し三角はマスコット表示に合わせ、キャラクター方向（上向き）を既定に修正しています。
- マスコットウィンドウは `frame: false` / `transparent: true` / `backgroundColor: '#00000000'` を維持し、通常表示で不要な枠やタイトルバーを出さない方針です。
- メイン画面のモデル管理UIで使う選択枠は維持しますが、マスコットウィンドウの通常表示には適用しません。
- マスコットウィンドウの吹き出しは、画面下固定ではなくキャラクター近く（頭上付近）に小さく表示する方針です。
- 現時点では頭上付近の簡易配置で、将来的にはVRM頭ボーン座標へ追従する配置へ拡張予定です。
- Alt+Tab などの復帰時にもタイトルバー/メニューバー再表示を避けるため、マスコットウィンドウ専用のクローム設定を再適用する構成にしています。
- 設定画面で `常に前面に表示` を ON/OFF できます（初期値は OFF）。
- ONにするとマスコットが他ウィンドウより前面に出るため、作業の邪魔になる場合はOFFを推奨します。

## マスコットウィンドウ移動方式（2026-04-25更新）

- マスコットウィンドウは `Ctrl / Shift + 左ドラッグ` で移動できます（初期値）。
- 移動方式は設定画面の `マスコット操作` から変更できます。
- 通常クリックはマスコット反応（吹き出し更新）に使用します。
- `透明なドラッグ領域を使う` モードは選択可能ですが、クリック反応と干渉する場合があります。
- ウィンドウ位置の永続化は現時点では未対応です。

## フォーカス喪失時タイトルバー対策（2026-04-28更新）

- Windows 環境では、`frame: false` + `transparent: true` のマスコットウィンドウでフォーカス喪失時にネイティブタイトルバーが再表示されるケースがあります。
- 回避策として、設定画面に `マスコットウィンドウにフォーカスを持たせる` を追加しました（初期値: OFF 推奨）。
- `mascotFocusable` が OFF の場合、マスコットウィンドウは `focusable: false` で作成します。
- デバッグでマスコット側を直接操作しづらい場合は、同設定を ON に戻して確認してください。
- `常に前面に表示`（`mascotAlwaysOnTop`）と併用できます。
- `focusable` 変更は環境依存差分を避けるため、次回起動時反映として扱います。

## AppSettings 永続化（2026-04-28更新）

- `AppSettings` は main process 側で JSON 永続化されます。
- 保存先は Electron の `userData` 配下 `settings.json` です。
- `settings.json` が存在しない場合はデフォルト設定で起動します。
- `settings.json` が破損している場合は、デフォルト設定へフォールバックします（アプリは継続）。
- 設定をリセットするには `settings.json` を削除してください。

## ユーザーデータ保存先変更（2026-04-28更新）

- `設定` タブの `保存場所` セクションからユーザーデータ保存先を変更できます。
- 保存先管理は `bootstrap.json` で行います。`bootstrap.json` はポータブル運用ではアプリルート直下に保存されます。
- 実データの `settings.json` / `responses.json` は `bootstrap.json` が指す保存先に配置されます。
- 保存先変更時は既存 `settings.json` / `responses.json` を新しい保存先へコピーします。
- コピー先に既存ファイルがある場合は日時付きバックアップを作成してから上書きします。
- 変更は安全性優先で次回起動時に確実反映されます。
- `初期保存先に戻す` でアプリルート配下 `user-data` へ復帰できます。
- トラブル時は `bootstrap.json` を削除すると、既定のポータブル設定で再生成されます（書き込み不可環境ではOS標準へフォールバックする場合があります）。
- 開発向けに `プロジェクト内 user-data を使う` ボタンを用意しています。

## ポータブル保存方式（2026-04-28更新）

- Chararium はポータブル保存を既定として起動します。
- 開発時はプロジェクトルート（例: `E:\Dev\Chararium`）をアプリルートとして扱います。
- 配布時は `Chararium.exe` があるフォルダをアプリルートとして扱います。
- 保存構成:
  - `アプリルート/bootstrap.json`
  - `アプリルート/user-data/config/settings.json`
  - `アプリルート/user-data/config/responses.json`
  - `アプリルート/user-data/electron/*`（Electron / Chromium 内部データ）
- Electron `userData` は起動初期に `app.setPath('userData', '<appRoot>/user-data/electron')` で設定します。
- `bootstrap.json` はアプリルート直下に固定され、`userDataDirectory` は既定で `./user-data` を指します。
- 旧構成で `user-data` 直下に存在する `settings.json` / `responses.json` は、`user-data/config` に同名ファイルがない場合のみ初回にコピーします。
- 旧構成で `user-data` 直下に存在する Electron 内部データは手動削除可能です。新構成では `user-data/electron` 配下に生成されます。

## ローカルセリフ辞書と時報（2026-04-28更新）

- ローカル返答は `userData/responses.json` のセリフ辞書で管理します。
- 初回起動時は `assets/responses/defaultResponses.ja.json` を元に `responses.json` を自動作成します。
- `responses.json` が壊れている場合は初期辞書へフォールバックし、アプリは継続します。
- 設定画面に `セリフ管理` セクションを追加し、カテゴリ有効/無効、セリフ追加・編集・削除・リセットを実行できます。
- クリック反応は辞書からランダム抽選され、`enabled` と `weight` を反映します。
- 時間帯判定ルール（ローカル時刻）:
  - morning: 5:00 - 10:59
  - afternoon: 11:00 - 16:59
  - evening: 17:00 - 20:59
  - night: 21:00 - 23:59
  - lateNight: 0:00 - 4:59
- 時報機能を `時報を有効にする` で ON/OFF できます（初期値 OFF）。
- 時報は毎時00分に1回だけ発火し、同一分で重複発火しないよう抑止しています。
- 深夜 quiet hours は初期値で有効（0:00-6:00）です。
- セリフ辞書のリセットは `初期セリフに戻す` または `responses.json` 削除で行えます。

## セリフ管理タブUI（2026-04-28更新）

- `時報テスト` ボタンで時報トリガーのセリフを吹き出しに即時表示できます。
- セリフ辞書の保存場所は管理タブ内に表示しています（`userData/responses.json`）。

## 追加仕様メモ（2026-04）

- 保存場所UIは `変更可能 / 自動決定 / 固定` で表示を分離しました。
- 変更できるのは `ユーザーデータ保存先` のみです。
- `settings.json` / `responses.json` は選択した保存先配下に自動配置されます。
- `bootstrap.json` は保存先記憶用のため Electron 標準 `userData` 配下に固定です。
- 保存先変更時は `settings.json` / `responses.json` のコピー結果をUIに表示します。
- 既存データがない場合は「次回起動時に初期生成」として表示します。
- マスコット設定に開発用 `マスコット当たり判定を表示` を追加しました。
- マスコット設定に `クリック透過` を追加しました。
  - `無効`
  - `常に下のウィンドウへクリックを通す`
  - `Ctrl/Shift押下中のみクリックを通す`
- セリフ時間指定は `HH:mm:ss` 形式を優先しました（`HH:mm` も受理して正規化）。
- 旧形式 `startHour` / `endHour` / `minute` は互換読み込みを維持しています。
- 時間帯判定は日跨ぎ（例: `22:00:00` - `02:00:00`）に対応しています。
- 透明マスコットウィンドウは当たり判定を縮小する方針で、初期サイズを小さめに調整しました。
- マスコットサイズは `小 / 中 / 大 / カスタム` から選択可能です。
- `マスコット表示サイズ`（見た目）と `マスコット領域サイズ`（BrowserWindow実寸）を分離しました。
- 領域サイズは実際の透明ウィンドウ矩形を変えるため、下層アプリのクリック妨害範囲に直接影響します。
- サイズ系設定は即時反映ではなく、`マスコット表示へ反映` ボタン押下時にまとめて保存・反映します。
- マスコット設定では「現在値」と「編集中の仮設定」を分けて表示します。
- 領域サイズ反映時は main process で `BrowserWindow.setContentSize(...)` を優先し、必要時のみ `setSize(...)` を補助的に使います。
- 反映結果は `指定領域サイズ / ウィンドウ実サイズ(getSize) / コンテンツ実サイズ(getContentSize)` を分けて表示します。
- `小: 200 x 360` 指定で `300 x 360` に見えるケースは、ウィンドウ外形サイズとコンテンツサイズの差（環境側制約含む）を切り分けて確認します。
- サイズ下限はコード上で `幅120 / 高さ180` に緩和していますが、環境によっては OS/Electron 側制限で指定値より小さくならない場合があります。
- `マスコット表示サイズ` の `custom` は表示倍率入力（0.3〜2.0）で制御します。

## 吹き出し幅・高さモード（自動 / カスタム）

- マスコット設定のレイアウト設定で、吹き出し幅・吹き出し高さそれぞれに `自動` / `カスタム` を追加。
- 初期値は幅・高さともに `自動`。既存設定にモード項目がない場合も `自動` 扱いで安全に補完。
- `カスタム` を選択した場合のみ、数値入力（幅 / 高さ）を反映。
- 横書き / 縦書きの両方で同じモードを使用し、プレビューと実表示の双方へ反映。
- マスコット設定初期化では、幅モード・高さモードを `自動` に戻す（既存どおり draft のみ初期化）。
- カスタム入力範囲は `幅 80〜800` / `高さ 40〜800`。
- 反映操作は下部の `マスコット表示へ反映` ボタンへ一本化し、上部は未反映状態の案内のみ表示。
- `auto` は固定幅/固定高さを解除し、本文に応じた自然サイズで表示。
- `custom` は実表示/プレビューの両方へ同じ幅・高さを反映。
- 未反映判定は幅/高さモードを正規化して比較し、`auto` 時はカスタム数値差分で未反映扱いにしない。
- 吹き出し幅は外枠だけでなく本文の折り返し幅に直接反映する（`custom` 250/400/600/800 で差が出る）。
- 横書きは `word-break: keep-all` / `overflow-wrap: normal` を基本にし、不要な1〜2文字改行を抑制する。
- 吹き出しサイズは外枠要素と本文ラッパー要素の両方に適用し、外枠だけ変わって本文幅が固定される状態を避ける。
- 吹き出しX/Yは吹き出し全体の位置調整（配置コンテナ）に適用し、幅/高さは本文領域のサイズ調整として分離しています。
- 吹き出しYは `+` で下方向、`-` で上方向へ移動します。三角X/Yは三角部分だけを調整します。
- `常に表示` は最前面固定（always-on-top）のON/OFFであり、表示/非表示の切替には使いません。
- フォーカス外れ（blur）を契機にマスコットを自動で `hide` しない構成にしています。
- 吹き出し三角はひし形ではなく、明示的な三角形として描画します。
- 三角設定は `translate(X,Y) + rotate(角度)` を合成して適用し、三角X/Yと角度を同時に反映します。

## 追加メモ（反映ボタン一本化・三角レイヤー）

## 追加メモ（吹き出し全体枠線・三角向き/反転）

- `吹き出し枠線` は三角単体ではなく、吹き出し本体＋三角を含む全体の枠線として扱う。
- 枠線 `ON/OFF` は本体と三角の両方に反映し、`OFF` では両方の枠線を消す。
- 三角は本体の前面に出しすぎない重なり順で描画し、本体と自然につながる見た目にする。
- 三角調整は `向き(auto/left/center/right)`・`反転`・`X/Y`・`サイズ`・`角度` を併用できる。
- 三角角度は「プラス値で右回転、マイナス値で左回転」として扱う。

## 追加メモ（focusable運用）

- `mascotFocusable` の既定値は `ON`（`true`）。
- `mascotFocusable` は通常設定ではなく開発者タブのデバッグ項目として扱う。
- 開発者タブの表示は「マスコットウィンドウを非フォーカス化する（デバッグ用）」で、既定は `OFF`。
- 上記デバッグ項目 `OFF` が通常運用（`mascotFocusable=true`）で、タスクバー/Alt+Tab 表示を維持する。
- デバッグ項目 `ON` では `mascotFocusable=false` となり、Windows でタスクバー/Alt+Tab に表示されない場合がある。
- `常に表示` は `alwaysOnTop` のON/OFFのみを扱い、`focusable` や表示/非表示制御とは分離する。
